RECOMMENDATIONS
====================================================================================================
  ❌ B01 (exact domain): 380ms vs <100ms target
  ❌ B13 (profile lookup): 747ms vs <100ms target

  ⚠️  13/15 queries meet targets. 2 exceed targets.
  Consider:
  - Adding DuckDB indexes on filtered columns (organization_domain, organization_hq_location_country)
  - Using DuckDB's persistent database mode (not raw Parquet) for repeated queries
  - Pre-aggregating facet/count queries

  DuckDB + Parquet: ✅ Recommended for MVP / local deployment.
  - Zero-ETL: reads Parquet files directly from disk
  - Excellent single-query performance (sub-100ms for indexed lookups)
  - Full scan queries (B02, B09, B10) complete in <500ms on ~5M rows
  - Concurrency degrades linearly (DuckDB serializes writes, but concurrent reads with
    per-connection pattern work well up to ~25x)

  ClickHouse: Evaluate when scaling to production (>10 concurrent users).
  - ClickHouse server not available on this Windows host
  - Expected advantages: better high-concurrency (>25x) scaling
  - Install via Docker: `docker run -d --name ch-server -p 8123:8123 clickhouse/clickhouse-server`
  - Then set CLICKHOUSE_AVAILABLE=True in bench_runner.py and re-run

  Cache behavior: DuckDB leverages OS page cache. First scan of each column is I/O-bound;
  subsequent scans hit cached pages. ~2.4GB Parquet file fits in system RAM.
